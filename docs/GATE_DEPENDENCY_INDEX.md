## Batch exit checklist
For each gate, the owning batch should record:

1. Serialized roots and transitive asset/script/component dependencies, including hashes and GUID crosswalks.
2. Runtime owners and lifecycle/event order, including teardown and failure behavior.
3. Existing tests reused, gaps in those tests, and the exact assertion added for the gate.
4. Full dependent test suite results and exact source SHA.
5. Release WASM/package manifest and independent integrity results before any site upload.
6. Device/backend evidence separately from headless assertions; identify the concrete device or backend needed to close any remainder.

A gate stays in progress until its batch evidence meets its acceptance conditions. “Still open” alone is not a batch result: record the specific failed edge, make a bounded fix, run the dependent checks, then advance to the next dependency.
