## Batch rules

1. Read the owning closure and confirm canonical archive, source snapshot, root profile, GUID/hash crosswalk and every serialized dependency before editing.
2. Capture source caller/callee order, init/update/fixed-update/teardown behavior, event listeners, random/time inputs, error cases and minimum observable assertions.
3. Batch all already-known asset/script/config/test prerequisites. When runtime reveals a new hidden dependency, stop that implementation batch, record the source/provenance edge and acceptance check, then resume the complete closure.
4. Run focused contracts, regression suites, pinned Release/WASM build, exact profile verification, and independent archive integrity checks on a single pushed SHA. Site source identity is a separate condition.
5. If platform evidence is impossible in this runner, name the exact capability and owner/device action; continue other independent source gates. Do not lower parity flags by substituting a weaker test.
