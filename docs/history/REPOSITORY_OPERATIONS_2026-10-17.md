## Workflow and branch housekeeping

- Audited **63 existing branches** (before maintenance branch creation), **4 open draft PRs** (#7, #42, #56, #57), **40 workflow YAML files**, and **17 open non-PR issues**. Several named `feature/`, `codex/`, `fix/`, `release/`, `maintenance/`, and `preview/` refs are historical checkpoints, not simultaneously active contributors. They may contain unique original-source recovery history, test evidence, rollback snapshots or compiled site files. **No mass deletion or forced rebases.**
- Existing gameplay PRs overlap conceptually but not safely interchangeable: #42 has recovered full-class source; #56 implements source projectile-to-limb injury; #57 targets weapon IK. Keep source ownership and integration paths separate until exact conflicts are resolved. The unreviewed `feature/original-projectile-hit-callback-sources` ref points to an older #56 SHA `69e6355`; inspect provenance before pruning.
- `vercel.json` on develop has `git.deploymentEnabled=false`. Do not enable automatic Vercel deployments. `pr-source-check.yml` runs fast scoped PR source tests; the full `wasm-arm-sequences.yml` has explicit manual dispatch and a feature/fix **workflow-file-only** push trigger. Unity WebGL is manual-only. Numerous historic audit/recovery workflows trigger only on editing their own YAML on specific historic branches; they are retained as reproducible evidence, not current active build jobs.
- `publish-original-mesh-viewer.yml` can trigger on `main` when `index.html` or its workflow changes, with `contents:write`; this is a legacy source-asset viewer workflow, not a Vercel auto-release. Treat modifications to this workflow as a separate reviewed task. Some source recovery workflows likewise have `contents:write`; do not generalize them into gameplay CI.
- The repo API listed no branch as GitHub-protected at audit. Repository documentation states review rules, but **documented rules are not enforced branch protections**; do not assert otherwise. Enabling enforceable protection/rulesets is a distinct administrator-level change needing confirmation.
- This maintenance PR adds root `.gitignore` for local secrets and build caches. **Never add broad patterns** for `*.wasm`, `*.obj`, `*.dll`, `*.gz`, `*.zip`, or `game/assets/**`: these can be original/reproducible source or intentional compiled snapshots. Existing committed files remain tracked regardless of ignore rules.
