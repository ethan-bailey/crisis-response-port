# Combat and physiology dependency closure — 2026-10-26

## Purpose and boundary

This inventory is the pre-implementation dependency closure for the source combat/injury gate. It distinguishes the already exercised single-hit path from unvalidated physiology, rendering, and physics subgates. Do not expand an implementation from a failing runtime assertion until the selected source snapshot, serialized component graph, script owners, update order, visual/audio assets, and acceptance assertions for that subgate are checked here and in the referenced machine-readable source package.

This closes the *inventory* for the combat/physiology gate as presently recovered. It does not claim all combat behavior is implemented or that the Unity game is at parity. Runtime failures may still reveal hidden dependencies, which must be added to this inventory with their source/provenance and then batched before the next implementation.

## Pre-implementation batch protocol

For each row before changing implementation:

1. Pin the recovered export SHA, source-index SHA, root/profile manifest and GUID/hash crosswalk for the selected actors, ammo and scene.
2. Query all prefab/scene component records and transitive object references for the row; inventory serialized values, curves, layers, masks, event listeners, resource lookups and nested prefabs.
3. Read the original owner methods and every caller/callee on the state path; capture lifecycle phases and update/fixed-update ordering, teardown and failure paths.
4. Name existing contracts and what each cannot prove; define the minimum state-transition assertions and fixture staging before editing.
5. Batch every dependency that is already visible in this inventory (assets, scripts, settings, browser/runtime bridge and tests) before implementation. Add new dependency edges only when an actual source/runtime observation reveals a genuinely hidden prerequisite.
6. Run the dependent suites on one exact pushed source SHA. Retain reports, package integrity evidence and artifacts. Do not deploy test-only changes.
7. Mark a dependency closed only at the level evidenced (source state, renderer output, browser audio, solver, device). Record blocked backend/device work with its concrete owner, required environment and next action.
