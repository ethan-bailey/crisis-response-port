## Loader and dependency-inventory touchpoints

At the observed branch source, `runtime/Engine/SceneLoader.cs` implements `ResolveScriptType`, `AssignBuiltinFields`, `AssignSerializedFields`, and `ReadValue`. Script resolution uses the filename derived from package `guidPaths`, preferring a unique `Crisis.Runtime.FullSource` component; so recovery must add the GUID-to-path to the generated execution package as well as the source type. Do not patch only the loader to alias a missing component.

`ReadValue` resolves Unity object references only from the current prefab's local fileID map. `AssignBuiltinFields` calls its external-reference handler for selected fields, but that handler marks nonzero references unresolved; it does not instantiate package assets. Completeness currently throws whenever unsupported components or unresolved references remain.

The deterministic source inventory is generated by `scripts/inventory_source_dependencies.py`; it reads checked-in sources under `runtime/Engine`, `runtime/Original`, and `source-reference`, the pinned archive index, and exact compiler baseline. Any recovered source addition must regenerate/review `docs/audit/source-dependencies.json`, retain the original Unity GUID mapping needed by prefab execution generation, and pass the ownership/source identity checks. The recovery archive pin is in the script.
